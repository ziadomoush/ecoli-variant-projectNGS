What we did and why

Assess base quality, adapters and biases across all six input files. FastQC 0.13 accepts --outdir; the attempted -o option failed. The MultiQC command is an equivalent invocation; its original command line was not retained in the bundle. Here raw names the analysis input, which is already trimmed. Mean Q is not the quality of every base. A GC warning alone does not establish contamination; the base-composition bias remains unexplained.

Commands used

Commands document the completed analysis. Shell loops apply the same procedure to each sample. They do not run in this website.

BASH · documented commands
fastqc -t 2 --outdir results/qc/raw data/reads/sub/*.fastq
multiqc results/qc/raw --outdir results/qc/raw

Understand the code

fastqc -t 2 --outdir results/qc/raw .../*.fastq

fastqc analyzes each matched file independently. -t 2 allows two input files to be processed concurrently; it does not combine R1/R2 into one biological sample. --outdir selects the HTML/ZIP report directory, which must exist. Output names derive from FASTQ filenames.

multiqc results/qc/raw --outdir results/qc/raw

MultiQC scans the directory for supported tool results and aggregates them into one report. --outdir sets the destination for multiqc_report.html. It does not reanalyze reads, trim them or align them. Avoid overwriting an earlier report unnecessarily.

Why --outdir?

The earlier -o attempt failed with FastQC 0.13 and did not produce QC results. The documented command uses --outdir. Analysis complete messages and resulting HTML/ZIP files indicate processing completed; assessing PASS/WARN/FAIL is a separate step.

What do statuses mean?

Statuses apply to different checks, not to a single overall sample validity score. Good base quality does not remove composition bias. Variable-length warnings are compatible with prior trimming; the actual bias mechanism was not established. Record warnings rather than automatically trimming solely because a module fails.

Cross-checking both reports

The individual FastQC report details 4863_R2; MultiQC summarizes the same analysis alongside five other files. These are not independent experiments. All eleven module statuses match, as do 175,000 reads and 50% GC. The individual report displays mean length as 123 bp, versus 123.85 bp in the more precise MultiQC data.

Commands used

Commands document the completed analysis. Shell loops apply the same procedure to each sample. They do not run in this website.

BASH · documented commands
curl -fL -o data/ref_genome/ecoli_rel606.fasta.gz https://ftp.ncbi.nlm.nih.gov/genomes/all/GCA/000/017/985/GCA_000017985.1_ASM1798v1/GCA_000017985.1_ASM1798v1_genomic.fna.gz

samtools faidx data/ref_genome/ecoli_rel606.fasta

Understand the code

curl -fL -o ...fasta.gz URL

Uses the previously explained curl options. The source is assembly GCA_000017985.1; fna denotes nucleotide FASTA. The local ecoli_rel606 filename is a convenient label and does not change sequence identity.

gzip -t ...fasta.gz

-t tests gzip integrity without creating an uncompressed FASTA. Silence with successful exit status means the compressed stream passed. It does not confirm strain identity or every base.

gunzip -k ...fasta.gz

gunzip decompresses gzip; -k keeps the compressed source and creates ecoli_rel606.fasta. Compression is not an alignment index. An existing output may trigger an overwrite question; there is no need to decompress again.

head -n 5 ...fasta

Shows the >header and sequence beginning. CP000819.1 is the contig name used in BAM, VCF and IGV; consistent naming is essential. FASTA does not contain per-base quality scores like FASTQ.

bwa index ...fasta

Builds index structures that let BWA search for read placements efficiently. Outputs include amb, ann, bwt, pac and sa files. It does not align reads or produce BAM. Build it before bwa mem on the same reference.

samtools faidx ...fasta

Creates fasta.fai containing sequence names, lengths and access offsets for rapid region retrieval. It serves reference access by downstream tools. It is distinct from BWA indexes and the BAM .bai index.

ls -lh data/ref_genome

Confirms the FASTA, compressed source and indexes are present. Keep them together. If the FASTA changes, old indexes may become invalid and should be regenerated for the new reference.

What we did and why

Align paired-end reads and assign read-group/sample metadata. -t 2 uses two threads. The shell expands sample names and BWA interprets the sequences in the read-group string. SAM is large; final alignments are retained as BAM.

Commands used

Commands document the completed analysis. Shell loops apply the same procedure to each sample. They do not run in this website.

BASH · documented commands
for sample in SRR2584863 SRR2584866 SRR2589044
do
  bwa mem -t 2 \
    -R "@RG\tID:${sample}\tSM:${sample}\tPL:ILLUMINA" \
    data/ref_genome/ecoli_rel606.fasta \
    "data/reads/sub/${sample}_1.trim.sub.fastq" \
    "data/reads/sub/${sample}_2.trim.sub.fastq" \
    > "results/bam/${sample}.sam"
done

Understand the code

for sample in ...; do ...; done

The loop iterates over three run IDs. Each iteration assigns one ID to sample, changing R1, R2 and SAM paths. do starts the body and done ends it. ${sample} inserts the value into filenames; braces delimit the variable name.

bwa mem -t 2

mem selects BWA-MEM alignment for these reads. -t 2 uses two alignment threads. Alignment places reads on the reference; it does not itself validate genetic variants. Variant calling occurs later.

-R "@RG\tID:${sample}\tSM:${sample}\tPL:ILLUMINA"

-R adds a read-group header. ID identifies the group, SM names the sample and PL names the platform. BWA interprets as tabs; double quotes allow ${sample} expansion. Giving all three runs the same SM would confuse sample identity downstream.

reference R1 R2

Positional arguments are reference FASTA, then R1 FASTQ, then R2 FASTQ. R1/R2 are paired ends; order and pair correspondence matter. The archived subsampled files are the inputs here.

> "results/bam/${sample}.sam"

> redirects stdout into SAM and overwrites an existing destination. BWA progress is normally sent to stderr, so it remains visible in the terminal. Real time indicates command completion; later BAM checks and flagstat assess output validity.

Backslash at line end

Continues the same shell command onto the next line; it must be the final character. It is not a BWA option or filename component. Losing it may cause a line to execute as an unintended separate command.

STEP 06 / 17

→

What we did and why

Repair mate information, sort alignments, mark duplicates and index BAM. The collate→fixmate -m→coordinate sort order supports this markdup workflow. Duplicates are marked, not removed from BAM here. FastQC sequence duplication and alignment duplicate marking are different measurements.

Commands used

Commands document the completed analysis. Shell loops apply the same procedure to each sample. They do not run in this website.

BASH · documented commands
for sample in SRR2584863 SRR2584866 SRR2589044
do
  samtools view -b -o "results/bam/${sample}.bam" "results/bam/${sample}.sam"
  samtools quickcheck -v "results/bam/${sample}.bam"
  samtools collate -o "results/bam/${sample}.collated.bam" "results/bam/${sample}.bam"
  samtools fixmate -m "results/bam/${sample}.collated.bam" "results/bam/${sample}.fixmate.bam"
  samtools sort -o "results/bam/${sample}.sorted.bam" "results/bam/${sample}.fixmate.bam"
  samtools markdup -s "results/bam/${sample}.sorted.bam" "results/bam/${sample}.markdup.bam"
  samtools index "results/bam/${sample}.markdup.bam"
  samtools quickcheck -v "results/bam/${sample}.markdup.bam"
done

Understand the code

samtools view -b -o OUT IN

view reads SAM and writes BAM with -b; -o selects the output. Binary conversion does not automatically sort alignments. OUT follows -o and IN is the final argument. The first .bam is an intermediate.

samtools quickcheck -v FILE

Rapidly checks the header and end-of-file marker. -v reports failing files; silence on success is expected. It does not read the entire body, so it cannot guarantee every record is intact. It is used after conversion and on final BAM.

samtools collate -o OUT IN

Groups records with the same read/template name so fixmate can access both mates. It is name collation, not genomic coordinate sorting and not necessarily a complete alphabetical name sort.

samtools fixmate -m IN OUT

Fills/corrects mate fields from name-collated or name-sorted input. -m supplies mate-score tags required for markdup. It does not call variants or realign reads to FASTA.

samtools sort -o OUT IN

Sorts by contig and genomic position by default, preparing input for markdup and indexing. Using sort -n would instead sort names and is not the required ordering at this stage.

samtools markdup -s IN OUT

Marks duplicate alignments in coordinate-sorted input using fixmate information. -s prints statistics; -r was not used, so duplicates remain in BAM. Zero optical counts do not establish their absence because optical detection was not enabled.

samtools index FINAL.bam

Creates a .bai for random regional access to coordinate-sorted BAM. It does not change reads. Keep it beside BAM and rebuild it if BAM is replaced. Successful indexing does not validate variant calls.

Understand the code

bcftools mpileup -f REF BAM

Understand the code

samtools depth -aa BAM

depth emits CHROM, POS and DEPTH. -aa includes zero-depth positions and unused reference sequences. Without zero positions, awk cannot measure gaps. Zero depth means no counted coverage under tool settings, not automatically a deletion.

$3 == 0 { ... }

awk tests depth field three. A zero starts or extends a run; default fields split on whitespace. The run logic assumes consecutive positions within one contig; it is appropriate for this single-contig project reference.

if (!run) {chr=$1; start=$2}

run initially evaluates to zero. !run means no gap is open, so contig and first zero position are stored. start stays unchanged while extending the gap.

end=$2; run++; next

end becomes the current position and run++ adds one zero-covered base. next moves to the next input line, preventing the following gap-print rule from running while a gap continues.

run {print chr,start,end,run; run=0}

On a nonzero-depth line with an open run, print the completed gap and reset run to zero. Output is chromosome, start, end and length, with both endpoints included.

END {if(run) print ...}

Prints any gap still open at end-of-file, preserving gaps reaching the sequence end. END runs after all input; next operates during individual line processing.

sort -k4,4nr | head -n 10

sort orders by field four alone: -k4,4; n requests numeric ordering and r reverses it so longest gaps come first. head -n 10 retains ten entries. Sorting does not merge gaps or turn them into variant calls.

$3 == 0 {

Understand the code

samtools depth -aa BAM

depth emits CHROM, POS and DEPTH. -aa includes zero-depth positions and unused reference sequences. Without zero positions, awk cannot measure gaps. Zero depth means no counted coverage under tool settings, not automatically a deletion.

$3 == 0 { ... }

awk tests depth field three. A zero starts or extends a run; default fields split on whitespace. The run logic assumes consecutive positions within one contig; it is appropriate for this single-contig project reference.

if (!run) {chr=$1; start=$2}

run initially evaluates to zero. !run means no gap is open, so contig and first zero position are stored. start stays unchanged while extending the gap.

end=$2; run++; next

end becomes the current position and run++ adds one zero-covered base. next moves to the next input line, preventing the following gap-print rule from running while a gap continues.

run {print chr,start,end,run; run=0}

On a nonzero-depth line with an open run, print the completed gap and reset run to zero. Output is chromosome, start, end and length, with both endpoints included.

END {if(run) print ...}

Prints any gap still open at end-of-file, preserving gaps reaching the sequence end. END runs after all input; next operates during individual line processing.

sort -k4,4nr | head -n 10

sort orders by field four alone: -k4,4; n requests numeric ordering and r reverses it so longest gaps come first. head -n 10 retains ten entries. Sorting does not merge gaps or turn them into variant calls.

The +1 accounts for inclusive endpoints. This ~44 kb length is a coverage observation, not a VCF event. Boundary clipping with supplementary MAPQ0 is not a reliable junction; junction evidence is needed before calling a validated deletion.

This is a static HTML website. No installation, database or build service is required to read it.

1. Open and review the website

Extract the ZIP first, then open index.html. Navigation, explanations, tables and included downloads work locally. Some original QC report features may rely on their own external assets or browser policies.

2. Add your original files

Copy the matching files from your completed project into the same relative folders here. Do not rename sample accessions or exchange R1/R2 files.

index.html
assets/
data/
  reads/sub/          # optional FASTQ inputs
  ref_genome/         # REL606 FASTA, indexes and GFF
results/
  qc/raw/            # FastQC and MultiQC
  bam/               # final markdup.bam + .bai
  vcf/               # raw, filtered and normalized VCFs
reports/             # tables, IGV evidence, report and slides
scripts/             # mapping and validation helpers

After adding files, run this from inside the website folder:

python3 scripts/refresh_manifest.py
python3 scripts/check_site.py

The updater changes file availability, size and text previews. The check script verifies included paths and local HTML resources. Neither script reruns the bioinformatics analysis.

3. Upload the extracted contents

Create a GitHub repository and upload index.html and its accompanying folders. The ZIP itself is a delivery package, not the website entry page. Keep index.html at the repository root.

4. Enable GitHub Pages

  1. Open the repository’s Settings → Pages.
  2. Under Source, choose Deploy from a branch.
  3. Select main and /(root), then Save.
  4. Use the website URL GitHub displays when deployment completes.

5. Check what a visitor can access

Open the published site, visit Project files and use Check uploaded files. Open the PDF, MultiQC, one VCF download and several IGV images. Expected files are not public until you upload them.

GitHub file sizes

Browser uploads allow up to 25 MiB per file. Regular Git uploads block individual files larger than 100 MiB. Use an appropriate external download or release workflow for large data; do not treat a Git LFS pointer as a working scientific data download.
